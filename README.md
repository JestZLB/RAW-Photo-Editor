# Luma Portrait · AI 人像修图

基于 [架构基线](docs/architecture-v4.html) 实现的 Windows-first 桌面人像修图工程：Tauri 2 + React 19 + TypeScript + Vite 前端，Rust 领域库与 CPU 图像管线，SQLite 持久化，可插拔云端 AI Provider。

当前状态是**可运行的架构基线**，不是完成品。所有未接入的模型与后端都会在界面和文档中如实标注，不会伪装成已实现能力。

## 快速开始

前置条件：

- Windows 10/11 x64
- [Bun](https://bun.sh) 1.3+
- Rust 1.88+ 与 MSVC Build Tools
- WebView2 Runtime（Windows 11 通常已内置）

```bash
cd code
bun install

# 浏览器演示模式（本地近似渲染，不启动 Tauri）
bun run dev

# Tauri 桌面应用（真实 Rust 渲染与 SQLite 持久化）
cd apps/desktop
bun run tauri dev
```

> 内置 Photo-HQ 权重（`apps/desktop/src-tauri/resources/realesrgan/models/Photo-HQ-W4xEX.{param,bin}`）
> **不随仓库分发**：上游未对该权重单独声明许可证，`.bin` 约 64 MB。缺失时应用正常运行，
> 只会在 AI 降噪能力预检中报告不可用并自动回退普通降噪。需要该能力时，按
> [`MODEL-NOTICE.md`](apps/desktop/src-tauri/resources/realesrgan/models/MODEL-NOTICE.md)
> 从上游更新包取回这两个文件放到同一目录即可，无需改代码或配置。

生产构建：

```bash
bun run build          # 仅前端
cd apps/desktop
bun run tauri build    # Windows 安装包（需要签名配置才能分发）
```

## 已实现

- 非破坏式项目：一个项目就是一组照片。原图只读引用，图层参数与 AI 结果独立保存；SQLite 自动保存，重开项目恢复。关闭窗口前会把尚未提交的调整落盘；写入失败时状态栏显示「保存失败」，不会假报已保存。
- 导入 JPEG / PNG / TIFF / WebP；桌面版提供 rawler 基础 RAW 解码；位图与 RAW 都会应用 EXIF 方向（RAW 通过 rawler 元数据读取 Orientation），并生成预览代理与缩略图缓存。旧 RAW 项目若尚未转正且没有坐标类编辑，打开时会自动旋转画布、预览、缩略图与裁剪范围；编辑过的旧项目不做自动迁移，建议重新导入。初始画布始终按原图（应用方向后的）宽高比适配显示。
- 线性 sRGB 色彩管线：曝光、对比度、高光/阴影、白色/黑色色阶、色温/色调、饱和度、鲜艳度、清晰度、锐化，以及整体 HSL（色相 / 饱和度 / 明度）。
- 细节与效果：降噪以总开关组织——开启后显示降噪强度与色彩降噪，并可勾选 AI 降噪；暗角、胶片颗粒、去雾（暗通道）与紫绿边校正保持独立可调、可复位，非零时自动回退 CPU。
- AI 降噪可用性预检：首次启用 AI 时先用 32×32 小块实跑一次内置引擎，检测 Vulkan/权重/路径；Photo-HQ 不可用时自动尝试已配置的 ONNX，两者都不可用或正式运行失败则自动回退普通降噪，并禁用 AI 选项、显示原因。AI 结果图层的强度由图层不透明度控制，关闭 AI 会隐藏图层并恢复普通降噪。
- 曲线与色阶：5 点 RGB 主曲线可拖拽，支持输入/输出黑白色阶与中间调；非默认值自动回退 CPU。
- LUT 风格：导入 `.cube`（1D / 3D），在显示 sRGB 空间套用并可调节 0..100% 强度；文件托管在项目资产目录，文档只记录引用，移除或调整强度同样可撤销。
- 本地 AI 降噪：内置 **Photo-HQ-W4xEX**（Real-ESRGAN 4x，随应用打包的 ncnn 引擎，GPU/Vulkan；最长边 1600px 输入 → 4x → 缩回原尺寸），也可切换到自备 ONNX 模型（纯 Rust tract、CPU、192px 分块）。两者都保存为独立 AI 结果图层，强度由图层不透明度控制，原图不变、可关闭对比或撤销；引擎能力会在首次启用时自动检测并回退。Photo-HQ 运行期间显示已用时间并可随时取消，取消会终止本地引擎进程且不产生图层。内置权重的授权边界见 ADR-011，自备模型见 ADR-010。
- 导出元数据：可选保留 EXIF（自动归一方向、移除过期内嵌缩略图）、去除 GPS 的隐私模式，或完全不写；TIFF 通过编码后追写 IFD 携带 EXIF；写不进去时如实回报，不假装写入。
- 16 位导出：PNG/TIFF 在 CPU 线性管线中渲染后量化为 RGBA16，暗部层次不因 8 位截断丢失；JPEG 请求 16 位会被明确拒绝。
- 色彩管理：导入时读取内嵌 ICC 配置（sRGB / Display P3 / Adobe RGB / 其他 RGB 矩阵配置），转换到线性 sRGB 工作空间并在照片面板标明来源；导出可选 sRGB、Display P3 或写回原图配置（PNG `iCCP` / JPEG `APP2`），不会生成未标注的广色域文件。
- 白平衡：吸管点击中性灰自动求解色温/色调；也可直接拖「色温」「色调」，白平衡独立成组并有单独复位。
- 调色辅助：RGB/亮度直方图实时反馈；“自动校正”按源图直方图给出带高光保护的曝光、对比与黑白场修正。
- 人像基础处理：肤色范围识别、频率分离式磨皮、细节保留、肤色均匀、自然提亮。
- 肤色美颜：自然美白（可调冷暖倾向）、红润气色、眼袋阴影。美白只做视觉提亮与黄气减轻，不承诺改变真实肤色；眼袋只处理袋状阴影，不做结构重塑。
- 精细修复：眼睛提亮、牙齿美白、黑眼圈、全部细纹（额头、眉间、鱼尾、法令纹、嘴角、眼下、颈纹可独立开关），以及瑕疵、痣、雀斑、胎记、纹身淡化。效果只作用在实测的眼睛、嘴、牙齿与人脸椭圆内；几何随人像图层保存，预览与导出不重复检测，未测量到的部位按人脸比例定位。牙齿按低饱和高亮门限美白，不会漂白嘴唇；斑点修复用局部高反差缺陷抑制，并避开眼睛、眉毛和嘴唇。
- 身体美颜：独立的「身体美颜」图层，使用身体肤色范围并避开当前选中的人脸；提供身体磨皮、美白、瑕疵、匀肤、提亮与纹理修整。背景灰墙、黑衣等低饱和区域会被色度门限排除。身体塑形（收窄 / 腿部拉长）只作用于该图层的修饰范围：先涂抹身体或腿部，再调强度；面部自动保护，蒙版外像素保持不变。
- 像素蛋糕式细分：磨皮半径、美白通透、去油光、眼白提亮、虹膜细节、牙齿亮度、眼影、眉色、唇色与冷暖、鼻影都可独立调节；面部塑形拆成瘦脸、下颌线、下巴长度、眼距、大眼、瘦鼻。另提供「奶油肌」「氧气感」「舞台妆」组合预设，预设只是可编辑参数组合，应用后仍可逐项关闭或归零。
- 按操作习惯分区：人像面板分为「皮肤 / 五官 / 妆容 / 脸型 / 身体 / 高级」六个粘性标签，人脸缩略图与重新检测常驻在顶部，快速风格改为紧凑胶囊并排显示；瑕疵、色斑归入皮肤，眼牙细节归入五官，眼影/眉色/唇色/鼻影归入妆容，区域识别与几何诊断收进高级，切换标签自动回到顶部。每张检测人脸可单独忽略或恢复，被忽略的人脸不再参与选择和画布叠加。修饰工具按「修复 / 液化」分组，`[` `]` 在修饰工具下也能调整笔刷大小。
- 面部塑形：瘦脸、大眼、瘦鼻在颜色处理前对合成画面做局部逆向变形，权重在脸缘前收敛到零，保持背景直线；作为人像图层参数保存，可归零或撤销。
- 局部蒙版：调色/人像图层可用画笔涂抹、擦除、清除，可添加线性/径向渐变并拖动端点，可放入五官区域椭圆，也可一键启用启发式自动肤色范围；支持反转、全局羽化与浓度。坐标绑定原图，裁剪后仍对齐。
- 内置 CenterFace + YuNet 双模型人脸检测：完全本地 ONNX 推理（tract），进入人像工具即自动检测；两个模型交叉验证并合并人脸框，编号按画面从左到右，默认选中置信度最高的一张。相比单模型，对舞台灯光、合影、侧脸与遮挡更稳；导入时已完成方向校正，检测侧不再做四方向扫描。
- 多人脸逐人调整：面板顶部列出全部人脸（带脸部缩略图），可单独选中；预设或效果开关会自动为所选人脸创建带脸部蒙版的独立人像图层，每张脸可分别设置程度、开关与区域，互不影响。
- 局部修复与液化：修复画笔（镜像取样并按周围环形颜色对齐）、克隆图章（Alt 取样）与推拉/收缩/膨胀液化，以非破坏的「局部修复」图层保存，逐笔可撤销；液化强度可调，并提供冻结保护画笔，涂过的区域不会被后续液化移动。含该图层的文档自动回退 CPU 渲染。
- 五官区域分析：在人脸框内以纯本地像素证据测出眼睛、眉毛、嘴、唇、牙、鼻与皮肤的椭圆区域及关键点，逐个带置信度；分析在 1600px 源图代理上进行，区域坐标按代理尺寸归一化后再写入文档，避免大图缩放后位置偏移。进入人像工具并在检测到人脸后自动测量一次，结果按项目缓存；精细修复的人脸几何随图层保存。多人照片按所选人脸显示与加入蒙版；每张人脸的美颜层默认带一个“人脸范围”蒙版，可再把眼周、皮肤等区域加进去。检不出来即省略，不做猜测，也不是逐像素语义分割（见 ADR-009）。检错或遮挡导致位置偏移时，可在高级页开启「调整五官位置」，在画布上拖动脸型/眼睛/眉毛/嘴/唇/牙/鼻椭圆，或拖右侧/下方圆点调整范围；修改写入当前人脸图层的几何并生成一条可撤销历史。
- 非破坏性裁剪：画布拖动、自由/1:1/4:5/3:4/16:9 比例、±45° 自定角度旋转（完整画面旋转，裁剪框保持竖直；旋转时裁剪框自动内缩到安全区域，不会框到透明角），可撤销；原图与图层参数不变。
- 图层：人像 / 调色 / AI 结果图层，可见性、不透明度、混合模式、排序、复制、删除；base 图层受保护。调色/人像参数可复制到另一张照片复用。
- 一条拖动一条撤销记录；撤销/重做；按住看原图；可拖动分屏对比（裁剪后仍对齐）；缩放/平移画布。
- 设置页：预览画质（1200/1600/2048）、导出默认值、人像预设程度、六套主题（墨蓝 / 暖砂 / 石墨 / 松柏 / 夜紫 / 浅色，一键切换并持久化）、减少动画、AI 降噪默认引擎（内置 Photo-HQ / 自备 ONNX）、默认强度与模型选择、AI 模型/能力与工作区诊断；偏好保存在本机，不可用时自动回退。导出对话框可配置水印（文字或透明 Logo、位置、不透明度与大小），设置会记住，只作用于导出文件。
- 项目管理：照片与缓存区可内联重命名、删除单张照片（含本地资产）与清理旧预览缓存；项目（照片集）在顶部「项目」菜单中切换并支持整体重命名，每个项目只展示自己的照片。
- 菜单与照片集：顶部左侧依次是「文件 / 项目」菜单、新建项目与设置；「新建项目」先命名照片集，再选择第一张照片创建。「导入照片」与 Ctrl+O 支持一次多选，照片按顺序导入并显示进度，单张失败不影响其余照片；未打开项目时第一张创建新照片集，其余自动加入同一集。可先创建空照片集再导入照片；底部照片集只列出**当前项目**的照片，可勾选多张并按当前导出格式/质量、各自裁剪后的原尺寸批量导出到指定文件夹（桌面版），显示逐项进度；也可把当前照片的调色图层一键同步到所选照片（含 LUT，各项目可单独撤销），裁剪、人像与修复不同步；「添加照片」同样支持多选加入当前项目。编辑区不再陈列其他项目。
- WGPU 本地渲染：基础照片、调色（不含清晰度/锐度）与 AI 结果图层在兼容文档上加速预览和导出；包含人像图层或局部清晰度/锐度的文档自动回退 CPU，界面显示实际后端。
- 导出 JPEG / PNG / TIFF / WebP（无损，sRGB 8 位），支持原图、1:1、4:5、3:4、16:9 与自定义宽高；JPEG 可选 1–100 压缩质量；临时文件 + 原子替换，禁止覆盖原图。导出显示阶段进度并可取消，取消不会留下半成品。可选水印（文字或 Logo）在最终输出尺寸上合成，支持五档位置、不透明度与短边比例，单张与批量导出都生效。
- AI Provider 契约与能力声明、本地 Mock Provider、OpenAI 兼容图像编辑适配器、模型列表拉取、上传确认、进度/取消、结果作为新图层、Windows Credential Manager 保存密钥、SSRF 防护。兼容代理地址可以粘贴完整 `/images/edits` 或 `/models` 端点，会自动归一化到 API 根；localhost 代理直连、绕过系统 HTTP 代理；远程地址在未配置系统代理时会预解析 DNS 并拒绝私有/链路本地结果。
- 浏览器演示模式：无 Tauri 环境下可用本地近似渲染完整走通界面与流程（会明确标注“演示模式”）。
- 内存与缓存纪律：预览 PNG 按「项目 + 尺寸」只保留最近 2 张（不再随 revision 无限堆积），并会删除高于当前 revision 的崩溃残留预览，避免旧会话文件反向淘汰新渲染；撤销/重做各上限 60 步，且两者合计的估算内存上限为 32MB（按蒙版点/区域/修复点与字符串容量估算，不做序列化），超出时先丢最旧的撤销记录、再丢最旧的重做记录；撤销/重做直接移动当前文档而不是再克隆一份；解析后的 `.cube` 跨帧复用；CPU 合成跨图层复用同一块缓冲，不逐层克隆整幅线性图；预览直方图在缓存命中时直接复用，不再为分箱重新解码 PNG。全分辨率源图缓存总预算 256MB，超过时按最近最少使用释放；单张超过 128MB 的照片不进入缓存，避免 100MP 图常驻数百 MB。自动校正、白平衡、人脸检测与五官区域只读取 1600px 源图代理（人脸检测再缩到 800px 跑双模型）；1600px 及以下的预览在裁剪范围足够大时也直接用这份源图代理并等比缩放裁剪坐标，全幅调色不再解码 100MP 原图；微小裁剪与 2048px 预览仍使用全图。预览中间图上限 4096px，避免为 1600px 预览生成 8192px 的线性中间图（16 B/像素）。演示模式的解码原图放进上限 6 张的 LRU，LUT 与任务列表同样有上限，删除项目时一并驱逐；切换项目会清空人脸区域与 LUT 会话状态。项目列表最多 100 条、AI 任务列表最多 50 条，避免长期使用后 UI 持有无限历史。解码后的 1600px 源图代理按项目保留在内存（最多 3 个打开项目，每个约 10MB，带 asset id 校验，源图重写即失效），拖动滑块时不再每帧重新解码 PNG；源图重写时缓存同步丢弃。

## 键盘快捷键

| 操作 | 快捷键 |
| --- | --- |
| 切换工具：照片 / 裁剪 / 人像 / 调色 / AI | `1` – `5` |
| 撤销 / 重做 | `Ctrl/⌘ Z` / `Ctrl/⌘ ⇧ Z`（或 `Ctrl Y`） |
| 按住对比原图 | `空格`（按住；松开或窗口失焦即恢复） |
| 缩放 / 适应窗口 | `+` `-` / `0`（双击画布在适应与 100% 之间切换） |
| 删除选中图层 | `Delete`（原始照片与锁定图层不响应） |
| 调整画笔大小 | `[` / `]`（蒙版或修饰工具激活时） |
| 退出画笔 / 白平衡吸管 | `Esc` |
| 打开照片 / 新建项目 / 导出 / 设置 | `Ctrl/⌘ O` / `Ctrl/⌘ N` / `Ctrl/⌘ S` / `Ctrl/⌘ ,` |
| 关闭对话框 | `Esc` |

输入框聚焦、导出或设置对话框打开时，单键快捷键不会触发；焦点在按钮上时空格仍是原生激活。工具与缩放按钮的提示里标注了对应按键。

## 明确的边界

- **人脸检测（CenterFace + YuNet 双模型）与五官区域已接入，但没有分割模型**。区域是本地像素测量得到的带置信度椭圆，不是逐像素掩膜，侧脸、遮挡与浓妆会漏检；自动肤色蒙版同样是启发式范围识别。眼睛提亮、牙齿美白、黑眼圈、皱纹与斑点修复已按这些实测区域生效，但仍是局部启发式处理：眼睛/牙齿位置不准时效果会偏，大面积的胎记或纹身只能淡化，不可能完全无痕。身体肤色范围与液化位移都是启发式局部处理，不是语义分割；极端侧脸、遮挡、发丝与复杂背景仍可能留下轻微痕迹。液化提供冻结保护画笔与 16×16 网格保护（点格子冻结整块区域，裁剪后仍对齐）。
- **RAW 是基础解码**。已覆盖松下 RW2/RWL、尼康 NEF/NRW、索尼 ARW 等格式，并用松下 DC-FZ80、尼康 1 J1、索尼 DSC-RX100 样片验证导入/预览/导出；其他机型仍取决于相机数据库。rawler 使用 LGPL-2.1，分发前需完成合规审查（见 `THIRD_PARTY_NOTICES.md`）。
- **本地 GPU 渲染是子集加速，不是全功能 GPU 管线**。WGPU 目前覆盖基础照片、不含清晰度/锐度的调色、裁剪与 AI 结果图层；人像图层仍走 CPU。设备丢失恢复、显存预算与高分辨率分块尚未完成。**本地 GPU AI 生成**仍未实现；云端生成由服务商 GPU 执行。
- **内置 Photo-HQ 需要 Vulkan 与额外约 70MB**。权重来自 Waifu2x-Extension-GUI v3.115.01，上游未对权重单独声明许可证，对外分发安装包前必须确认授权；没有 Vulkan 时不会退化到 CPU，AI 选项会被禁用并回退普通降噪。输入上限为最长边 1600px，更大照片的细节来自 4 倍重建后再缩小。能力预检会真实跑一次 32×32 推理，首次启用可能多等几秒。
- **自备 ONNX 通道仍需符合尺寸契约**。输入 `[1,3,192,192]`、输出同尺寸，只支持去噪、不支持超分放大；CPU 推理速度取决于模型大小与照片分辨率，权重授权由来源决定。
- 裁剪已支持自由比例与 ±45° 完整画面旋转；透视校正尚未实现。
- 历史栈不跨重启；参数与图层状态会持久化。
- HDR、软打样、批处理、更新器、崩溃上报未实现；ICC 输入/输出已支持（PNG / JPEG / TIFF 均可携带），但基于 3D LUT 或 CMYK 的配置只识别不转换。
- OpenAI 兼容 Provider 已实现适配器与 SSRF 防护，但真实端点需要自行配置与联调；自动化测试只覆盖 Mock、URL 归一化/回环识别与校验逻辑。远程访问遵循系统 `HTTPS_PROXY`/`ALL_PROXY` 环境变量；使用代理时 DNS 由代理解析，应用不做本地解析预检。

## 数据存放与重置

- 数据库（`luma.db`）、项目资产与预览缓存位于 Tauri 的 app data / app cache 目录；Windows 上分别是
  `%APPDATA%\com.lumaportrait.editor` 与 `%LOCALAPPDATA%\com.lumaportrait.editor`。实际路径在设置页的「工作区诊断」中显示。
- 原图只被引用，不会被修改或复制进工作区；清空工作区只会丢失编辑参数、AI 结果与预览缓存，原图与服务商配置需要重新导入/填写。
- API Key 存放在 Windows 凭据管理器，服务名为 `com.lumaportrait.editor`、条目名为 Provider ID；
  它不进入 SQLite、前端持久化或日志，重新保存即覆盖。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 画布角标一直显示「CPU 渲染」 | 文档含人像图层、HSL、曲线/色阶、LUT 或局部清晰度/锐度时，按设计回退 CPU（见[兼容矩阵](docs/compatibility/matrix.md)），不是故障。 |
| AI 降噪开关不可用 | 缺少 Vulkan、内置权重缺失或 ONNX 路径无效。能力预检会给出具体原因；可在设置页切换到自备 ONNX 模型。 |
| 关闭窗口提示「保存失败」 | 3 秒内没有完成落盘（磁盘占用、权限或空间不足）。选择「返回」可继续编辑并重试保存。 |
| 重新打开项目后没有人像图层 | 人像参数随图层保存，原图不变；若曾删除该图层，需要重新应用效果或预设。 |

- 本地调色、人像、Photo-HQ 降噪与导出不会上传图片；Photo-HQ 由本机 ncnn 进程在 GPU 上完成推理。
- 云端 AI 必须由用户明确勾选上传确认；API Key 存于 Windows Credential Manager，不进入前端持久化、SQLite 或日志。
- Tauri capability 采用最小权限，仅开放核心接口与文件对话框；不开放任意文件系统或 Shell。
- 示例照片由 AI 生成，不对应真实人物。
- 人脸检测模型随应用本地打包，不上传照片。
