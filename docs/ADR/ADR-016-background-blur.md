# ADR-016：背景虚化图层

- 状态：已接受
- 日期：2026-11-06
- 关联：ADR-014 栅格蒙版、ADR-015 分割模型

## 背景

栅格蒙版与分割适配器就绪后，缺少一个「消费」蒙版的真实效果。人像修图里最直接的
消费方是背景虚化：分割给出主体，虚化只作用于主体之外。

需要决定：虚化是挂在调色参数里，还是成为独立图层？

## 决策

1. 新增 `LayerKind::Blur`，参数只有 `BlurParams { radius }`（最短边的 0..0.08）。
   挂进 `ColorParams` 会让「一个图层一种效果」的分层语义失效，也无法单独排序、
   显隐或与调色叠加。
2. **蒙版语义不变**：`LayerMask` 覆盖处就是效果生效处，与调色/人像图层一致。
   因此「保护主体」= 打开 `mask.inverted`，界面提供一键「保护主体」按钮，
   而不是为虚化单独定义反向语义。少一套语义，就少一处两端理解偏差。
3. 虚化图层支持手动画笔与智能蒙版（`set_layer_mask` / `apply_raster_mask`
   的允许种类都扩展到 `Blur`），这样「分割主体 → 反相 → 只虚化背景」是完整链路。
4. 实现为三次盒式模糊近似高斯：可分离 + 前缀和，每次 O(像素)，与前缀半径无关；
   alpha 保持不变，避免把半透明边缘一起抹开。三次是视觉上与高斯不可分辨的最小次数。
5. 演示后端用 Canvas `filter: blur()` 生成模糊层，再按同一蒙版逐像素混合，
   保证两端行为一致（不是「桌面虚化、演示不虚化」）。
6. 虚化半径随文档保存，跨重启与版本快照都能恢复；历史标签为「背景虚化」。

## 后果

- 优点：蒙版有了实际用途；虚化可独立显隐/排序，可与调色叠加；两端一致。
- 代价：虚化是**均匀模糊**，没有景深估计、没有光斑（bokeh）形状、没有边缘高光；
  半径以最短边比例表达，预览与导出按各自尺寸换算，因此大图导出的虚化强度与
  1600px 预览在视觉上接近但不逐像素相同（这是比例半径的固有属性）。
- 未覆盖：景深/深度图、镜头模糊的光斑、GPU 加速（虚化在 CPU 上执行，与其余
  CPU 基线一致）。

## 验证

- `blur_spreads_energy_and_leaves_alpha_alone`（render-engine）：单点能量扩散、alpha 不变。
- `zero_radius_blur_is_a_noop`：半径 0 不改像素。
- `blur_layer_smooths_only_inside_its_mask`（app-core）：棋盘图 + 左半栅格蒙版 +
  +0.08 半径，渲染后左半相邻像素对比度降到右半的一半以下，右半保持锐利；
  同时覆盖「新增虚化图层 → 写入参数 → 提交历史 → 挂载分割蒙版」全链路。
- `blurLayer.test.ts`（前端）：`editBlur` 立即更新本地图层，并经由轻量命令
  `update_layer_params_meta` 合并发送 `blur`（该用例发现并修复了参数队列遗漏
  `blur` 的缺陷）。
