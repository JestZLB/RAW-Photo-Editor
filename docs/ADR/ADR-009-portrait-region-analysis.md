# ADR-009：五官区域分析的证据式实现

- 状态：已接受
- 日期：2026-10-21
- 关联：ADR-001、ADR-003、ADR-004、IPC 契约

## 背景

磨皮、眼睛增强、牙齿美白这类功能要求知道"眼睛在哪里"。项目约束仍是离线、无 Python；早期 SeetaFace（`rustface`）只给到人脸框，没有 5 点或 106 点关键点，所以区域只能从像素里测量。现在改为 CenterFace + YuNet 双模型：两者同时输出人脸框和 5 点关键点，但当前区域管线尚未消费关键点，仍以像素证据为主；关键点对齐留作后续优化。

可选路线：（a）附带一个关键点网络权重并自己写推理；（b）从像素里量出来；（c）继续禁用。 (a) 与"纯 Rust + 离线 + 体积可控"冲突，且推理实现无法在本仓库内验证正确性。(c) 让人像模块长期停在演示状态。

## 决策

1. 采用 (b)：在人脸框内**测量**区域，而不是训练或推理出区域。每个区域都是一个带置信度的椭圆，不是逐像素掩膜。
2. 证据来源是三条互相独立的图像统计，全部在 56×56 网格上计算：
   - YCbCr 肤色轨迹（Cb 0.30..0.50、Cr 0.52..0.68 软边界）乘以亮度/绿度门控，得到逐格 `skin` 权重；
   - 眼睛与眉毛用"暗核 + 亮环"斑点检测：在某列上找暗中心被肤色亮环包围最强的位置，要求亮环至少有 12 格且平均肤色 ≥ 0.45；
   - 嘴部用红度一阶矩（`cr - 0.5` 加权质心），嘴唇/牙齿再由嘴内的亮度分割得到。
3. 只接受能通过一致性检查的结果：斑点与周围皮肤的亮度差 ≥ 0.05；两眼必须落在同一行（由更强的那只锚定）、两点中点落在皮肤连通域中心跨度的 14% 以内、水平间距不小于窗口宽度的 6%。任何一条不满足就丢弃该区域。
4. 检不出来就省略，绝不外推。头发区域在样片上会把额头误判成发际线，因此整个 `Hair` 类别被删除，而不是降低阈值凑数。
5. 分析结果不直接成为像素，而是成为文档数据：`MaskRegion`（schema 9）把检出的椭圆存进 `LayerMask.regions`，渲染端按旋转椭圆 + smoothstep 羽化合成到蒙版。用户可以只取其中一两个区域，也可以手动加第二个。
6. 结果按打开的项目缓存（`regions` / `regions_analysed`），人脸框也一并缓存（`detection`，分析代理尺寸）。源图在会话期内不可变，重复调用不再计算，区域测量可直接复用检测结果；关闭项目即失效。
7. 坐标系约定：分析内部使用分析代理的像素，交给前端前按**代理宽高**归一化（因此与源图的 0..1 坐标一致）；人脸框换算回源图像素。早期实现错误地按原图宽高归一化代理像素，导致 1600px 代理上的区域整体缩小、偏离人脸，现已修复。
8. GPU 回退规则保持不变：只要图层带活动蒙版就走 CPU 管线，区域椭圆也走这条路径。
9. 精细修复使用区域几何，但区域分析本身仍只提供**范围**：`eyeEnhance`、`teethWhiten`、`darkCircle`、`wrinkle` 以及 `blemish` / `mole` / `freckle` / `birthmark` / `tattoo` 由 CPU 管线按这些椭圆局部处理（见第 13 条）。没有几何时不猜测五官位置：眼睛、牙齿、黑眼圈与皱纹保持关闭，斑点修复退回肤色范围；UI 会在打开这些效果时先触发测量。
10. 方向处理：导入时已应用 EXIF 方向并自动修复无坐标编辑的旧 RAW 项目，因此检测侧只处理正向画面，不再做四方向扫描，避免双模型把耗时放大数倍。区域测量仍基于当前画面坐标。
11. 多脸工作流：进入人像工具自动检测全部人脸，左到右编号；列表带脸部缩略图并默认选中置信度最高的一张；用户选择任意脸后，区域列表与画布叠加切换为该脸。检测在 1600px 分析代理上缩到 800px，同时运行 CenterFace 与 YuNet（均为 MIT）：两模型框 IoU > 0.45 合并，置信度取平均并记录来源；单模型框需 ≥0.7 才保留。`confidence` 为 0..1，界面直接显示百分比，用于相对比较，不是校准概率。
12. 逐脸美颜图层：应用预设或效果开关时，为该脸创建 `PortraitParams.faceIndex` 标记的人像图层，并带一个 `kind = "face"` 的脸部椭圆蒙版；已有同脸图层则复用。`faceIndex` 只用于编辑归属，实际作用范围由蒙版决定；不同脸的图层独立撤销、独立强度。单脸照片若已有旧版全局人像层，继续复用，不强行拆层。
13. 肤色美颜、身体美颜与塑形复用同一份几何；没有分割网络时，身体范围由带色度门限的肤色启发式给出，并利用选中脸的椭圆把脸从身体层中排除。灰墙、黑衣、白衣因色度接近中性被排除，避免身体磨皮/提亮把背景一起抬高。塑形在颜色处理前对合成画面做逆向采样，权重在脸缘前降为零；手动液化复用「局部修复」图层，以笔触快照保证不会自我反馈。两者都不是语义分割，极端发丝、遮挡和复杂背景仍可能出现轻微痕迹。
14. 精细修复在 CPU 管线中消费几何（schema 15 的 `PortraitParams.geometry`）：眼睛在眼周椭圆内做局部反锐化并保护瞳孔；牙齿在牙/嘴椭圆内按高亮低饱和门限去黄；黑眼圈在眼下椭圆内提亮并中性化偏蓝阴影；皱纹只在额头、眉间、鼻唇沟与眼角区域压制暗线；斑点类效果用多尺度模糊参考 + 高反差门限压制缺陷，并以眼睛/眉毛/嘴/牙齿覆盖率做保护。没有几何时只保留斑点修复的肤色回退。几何随图层保存，复制到另一张照片时清空并按目标照片重新解析。
15. 手动校正：测量结果不是最终答案。用户可在画布上直接拖动脸型/左右眼/眉/嘴/唇/牙/鼻/颈椭圆移动位置，拖动右侧与下方圆点调整半径；改变只写入所选人脸图层的 `PortraitParams.geometry`，通过 `update_layer_params` 连续更新、指针抬起时 `commit_changes` 合并为一条「调整五官位置」历史。进入校正会自动创建或复用该脸图层，切换人脸、离开人像工具或打开其他项目时退出。校正后的几何同时驱动精细修复、妆容与面部塑形；蒙版不会自动跟随，必要时仍需手动调整修饰范围。

## 后果

- 优点：完全离线、零额外依赖与权重文件；每个区域都有可解释的证据和置信度；错误表现是"没有该区域"，而不是"位置离谱但看起来在工作"。
- 代价：精度上限远低于真正的关键点模型。侧脸、遮挡、强妆、极端光照下会漏检；椭圆也无法表达眼睑、唇线这类非凸轮廓。
- 因此文档与 UI 必须持续使用"估算/需确认"的措辞，`RegionMaskOverlay` 画出的是建议范围，用户点击后才成为蒙版。
- 网格统计代码是自研的，需要真实照片持续回归；合成脸只能保证几何关系正确，不能保证阈值合理。

## 验证

- `portrait-engine` 单元分析使用解析式合成人脸（眼睛、眉毛、嘴、皮肤位置已知），断言检出中心落在真值 5%~8% 容差内；平坦灰图、只有一侧有皮肤的图、退化框都返回空结果。另有横置样片回归：把打包人像顺时针旋转 90° 后仍能检出，并断言人脸框映射回旋转后坐标。
- `app-core`：对 6000×4000 实拍预览调用区域分析，断言归一化后的区域中心落在人脸框内（按 1600px 分析代理归一化），而不是被原图尺寸缩小 3.75 倍。
- `render-engine`：区域蒙版把调整限制在椭圆内、旋转角生效（`region_mask_limits_adjustments_to_an_ellipse`、`rotated_region_respects_its_angle`）。
- `app-core`：对打包样片调用 `analyze_portrait_regions`，断言一张脸、分数 > 0.4、左右眼/皮肤/嘴都存在且归一化、两眼的 y 相差 < 0.03；第二次调用返回完全相同的结果（缓存命中）；把左眼椭圆写进图层蒙版后提交历史、渲染预览（`backend = "cpu"`），关闭并重开服务后蒙版区域仍在。
- 真机（Windows 11，示例人像 768×966）：识别五官区域后得到 `脸部皮肤 95% / 左眼 75% / 右眼 75% / 左眉 55% / 右眉 55% / 嘴唇 90%`，牙齿与鼻未达阈值因此不显示；叠加层椭圆目视落在对应器官上。把"左眼"加入当前调色图层蒙版并将饱和度拉到 +100 后，逐点取样：左眼 RGB 从 `[167,139,127]` 变为 `[187,131,107]`，而同一行的右眼、双眉、嘴、额头、脸颊、头发与背景全部逐字节不变，状态栏显示 `CPU 渲染`。再次点击区域可移除，重开项目后区域仍在蒙版里。
- 多人脸真机：双人合成图与 P1023657.RW2 均能自动列出两张脸；P1023657 上 CenterFace/YuNet 对两位歌手的分数约为 0.79–0.90，合并后界面显示 81% / 83%，两张脸均标记“双模型”。为两张脸分别应用预设/磨皮后生成 `人脸 1 美颜`、`人脸 2 美颜` 两个图层，`faceIndex` 分别为 0/1，脸部蒙版中心落在各自人脸框内；把脸 1 整体程度改为 55 后，脸 2 仍为 78。区域识别切换人脸时，画布叠加与区域列表同步切换。
- 真机（P1023781.RW2，4000×6000）：双模型合并后仅保留主唱 1 张脸，界面置信度 86%，背景鼓手未达到单模型 0.7 的保留阈值。
- `portrait-engine` 精细修复单元测试：眼睛局部对比度上升且画布外像素不变；牙齿黄色分量下降而嘴唇逐字节不变；眼下阴影提亮；皮肤暗斑对比度下降；额头暗线被提亮；零参数逐字节无操作。
- `render-engine`：同一人像图层带 `geometry` 时眼下阴影提亮，去掉 `geometry` 后阴影不动（`portrait_fine_repair_uses_the_layer_geometry`）；区域蒙版在裁剪导出时仍按全画幅坐标对齐（`region_mask_stays_aligned_when_the_export_is_cropped`）。
- 真机（Windows 11，示例人像 768×966）：检测置信度 92%；开启全部精细修复后与关闭精细修复的预览逐像素比较，左眼平均差 2.33 / 最大 24，右眼 3.83 / 60，嘴部 1.4 / 52，额头 2.33 / 37，背景逐字节为 0；CPU 预览 216ms，800px 导出 500ms。
- 真机多人脸（示例人像左右镜像合成 1536×966）：自动检测 2 张脸（90% / 93%），默认选中第 2 张；在第 2 张上打开眼睛提亮自动创建 `人脸 2 美颜`（`faceIndex = 1`、几何来自实测），第 1 张眼睛区域逐字节不变；再选第 1 张打开同一效果生成独立 `人脸 1 美颜`，反复开关不重复建层。验证项目已删除，用户项目未改动。
- 真机皮肤美颜（示例人像 768×966）：美白 50 / 冷暖 12 / 红润 35 / 眼袋 45，叠加分区细纹后与关闭这些效果比较：额头平均差 2.15、脸颊 3.28、眼下 2.78，背景 0；身体层（磨皮 30 / 美白 40 / 瑕疵 50 / 匀肤 30 / 提亮 18 / 纹理 30）只在颈部 3.28、胸部 3.34 产生变化，脸部逐字节为 0，背景为 0；CPU 预览 281ms。
- 真机塑形（示例人像）：瘦脸 70 / 大眼 60 / 瘦鼻 50，与归零比较：下颌平均差 3.06、眼周 1.85、鼻部 2.19，背景 0；三条滑杆通过 UI 写入后图层参数保持 65/50/40，预览与导出均正常。
- 真机手动液化（示例人像）：在「修饰 → 推拉液化」中拖出 13 点笔触，保存为 `mode = push`、半径 0.03、强度 0.5；收缩与膨胀各追加一笔，三笔均持久化。用同一路径的局部推拉对比，笔触区域平均差 13.71、最大 165，背景 0。
- 真机导出：含美白/红润/眼袋/分区细纹/身体美颜/塑形/液化的项目导出 800px JPEG 用时 426ms，输出 636×800、后端 CPU，文件可正常解码。
- 真机细分参数（示例人像）：开启磨皮半径 60 / 美白通透 40 / 去油光 40 / 眼白 50 / 虹膜 40 / 牙齿去黄 50 + 亮度 40 / 唇色 40 + 暖 20 / 鼻影 30 / 瘦脸 60 / 下颌 60 / 下巴 40 / 眼距 20 后，与这些细分项归零比较：唇部平均差 16.14、鼻部 3.67、下颌 23.07、眼周 9.09、脸颊 9.16，背景逐字节为 0；CPU 预览 228ms。
- 真机 UI：高级肤色、五官细节、面部塑形均可展开并写入参数；六张快速风格卡片同时展示。应用「舞台妆」后图层确认写入 `eyeEnhance 50 / eyeWhite 40 / teethWhiten 60 / teethBrighten 20 / lipTint 45 / lipWarmth 20 / noseContour 25 / rosy 45 / smooth 24`，可继续逐项关闭。下颌线 50、下巴 30、眼距 -20 通过滑杆写入后图层参数一致。
- 真机 UI（示例人像）：人像面板改为皮肤 / 五官 / 脸型 / 身体 / 高级五个粘性标签，人脸缩略图与重新检测常驻顶部，六个快速风格胶囊两行排布；皮肤页含快速风格、整体程度、基础开关、肤色美颜与瑕疵色斑，五官页含眼牙唇鼻与分区细纹，高级页收拢数值滑杆、区域识别与几何诊断；切换标签自动回到顶部。修饰工具按修复 / 液化分组，液化改为紧凑胶囊；修饰工具激活时 `[` `]` 可调笔刷大小（实测 30 → 26）。
- 真机忽略人脸（双人合成图 1536×966）：忽略当前人脸 2 后，列表显示“1 张可调整 · 1 张已忽略”，人脸 2 缩略图变暗并显示“已忽略”，画布只保留人脸 1 的框；点击恢复图标后人脸 2 恢复并被选中，两张框重新出现。至少保留一张人脸，不能全部忽略。
- 真机冻结保护（修饰工具）：选择“冻结保护”拖出 13 点笔触，保存为 `retouch.freeze`，半径 0.03；点击“清除冻结保护”后计数归零。`render-engine` 增加冻结覆盖测试，完整覆盖时液化无法移动边界。
- 真机妆容：在“妆容”标签直接拖眼影滑杆会自动创建当前人脸的美颜层并写入 `eyeshadow = 60`；眼影/眉色算法单测分别验证只影响上眼睑与眉部椭圆，脸颊逐字节不变。
- 真机照片集重命名：通过项目菜单铅笔图标把“修复项验收”改为“修复项验收-已改名”，`list_projects` 中该集合全部照片同步更新；`app-core` 测试验证多照片集合、已打开会话与 revision 不变。用户项目未受影响。
- 预览缓存回归：开发重启后旧会话留下高于当前 revision 的预览文件，原先按 revision 保留会反向淘汰新渲染并让画布 404；`prune_render_previews` 现在会删除高于当前 revision 的不可达文件，再按 revision 保留最近两张，已加单元测试。
