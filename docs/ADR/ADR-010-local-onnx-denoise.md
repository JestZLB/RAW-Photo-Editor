# ADR-010：本地 ONNX 降噪（自备模型）

- 状态：已接受
- 日期：2026-10-22
- 关联：ADR-001、ADR-003、ADR-004、ADR-011、IPC 契约

## 背景

用户希望降噪能使用已知的 AI 去噪模型（参考 waifu2x-Extension-GUI 一类工具），而不是只用双边滤波。项目约束仍然是：照片不上传、纯 Rust 主流程、不引入 Python 运行时、编辑非破坏。直接附带权重会遇到两个问题：不同模型的许可证与再分发条款需要逐个确认，权重体积也会显著增大安装包。

最终落地为两个通道：本 ADR 描述的自备 ONNX 通道（通用、纯 Rust、CPU），以及 ADR-011 描述的内置 Photo-HQ-W4xEX ncnn 通道（固定权重、GPU）。两者共用“AI 结果图层”的保存与非破坏语义。

## 决策

1. ONNX 通道**不附带模型权重**。用户在设置页选择一个 `.onnx` 文件，路径与强度保存在本机设置（`localStorage`），只在桌面版启用；内置 Photo-HQ 不影响这条通道。
2. 推理由 `tract-onnx` 完成，纯 Rust、CPU、离线运行；不调用外部进程、不上传图片、不执行模型附带的脚本。加载与优化后的模型按路径缓存，只保留 1 个（模型权重可达数十至数百 MB，避免同时驻留两份），切换模型时重新优化。
3. 输入契约固定为 `[1, 3, 192, 192]` 的 float NCHW，数值为 sRGB 0..1；模型输出必须保持 192×192。这样只接受**保持尺寸的去噪模型**，超分放大模型会被明确拒绝，而不是静默改变分辨率。
4. 大图按 192px 分块处理，块间重叠 24px，边缘用 24px 羽化权重加权融合；图像边缘不足一块时按边缘像素钳制填充。累加缓冲使用 f32，最后除以权重并量化回 8 位。
5. 强度参数 0..1：`result = original + (model - original) * strength`；`strength = 0` 严格不改变像素。alpha 原样保留。
6. 输出编码为 PNG，登记为 `ai_result` 资产并生成 1600px 预览，文档新增一个 `aiResult` 图层（名称为“AI 降噪”），提交一条撤销记录。原图、已有图层与其它资产不被修改；关闭图层即可对比。
7. 模型加载失败返回 `AI_DENOISE_MODEL_INVALID`，推理失败（形状不符、运行错误）返回 `AI_DENOISE_FAILED`。错误信息说明输入/输出要求，不推测模型内部结构。
8. UI 必须区分“内置 Photo-HQ-W4xEX”与“自选 ONNX 模型”：后者由用户提供、CPU 推理、授权由来源决定；不能把自备模型说成应用内置能力。

## 后果

- 优点：完全离线、无 Python、无网络请求；用户可以按题材选择模型；ONNX 通道不必承担权重再分发风险；结果是非破坏图层，可对比、关闭、撤销。
- 代价：效果完全取决于所选模型。waifu2x 的 photo 模型在低噪人像上可能过度平滑皮肤纹理；不同模型的训练域、色彩偏移与输出尺寸假设都不同。固定的 192px 输入要求也排除了需要 256px 或任意尺寸输入的模型。
- CPU 推理比传统双边滤波慢得多，超大照片会分成很多块；当前没有取消按钮与进度事件，运行期间按钮显示“本地推理中…”。GPU 推理与模型内部分块尚未实现。
- 需要持续用真实模型回归：身份模型只能验证管线正确性，不能证明某个去噪权重的效果。

## 验证

- `ai-denoise` 单元测试：手写 ONNX 恒等模型（动态空间维、Identity 节点，105 字节）对 500×380 渐变图分块推理，通道误差 ≤ 1，证明分块、重叠与羽化无接缝；`strength = 0` 时 RGBA 完全不变；缺失文件返回加载错误。
- `app-core` 集成测试：用恒等模型运行 `run_ai_denoise`，断言新增图层 `kind = "aiResult"`、名称“AI 降噪”、拥有 `assetId`，预览可渲染，关闭并重开服务后图层仍在。
- 真机（Windows 11，示例人像 768×966）：设置页选择恒等模型后显示“已配置”，效果组显示“AI 降噪”和强度滑块；点击后生成“AI 降噪”图层与 1600px 预览，状态栏显示 GPU 渲染，原图图层保持只读。验证后删除测试项目并清除指向临时模型的设置路径。
