# ADR-001：内部像素表示与工作色彩空间

- 状态：已接受
- 日期：2026-10-20
- 关联：架构文档 04 / 07，IPC 契约 v1

## 背景

调色、磨皮和合成需要在明确的光照线性空间中计算，否则曝光、模糊与混合会产生不可控偏差。首期面向 Windows，且未验证 ICC / HDR 显示链路，需要避免用“支持 sRGB / P3”这样的标签替代真实色彩管理。

## 决策

1. 文件解码后先得到 8-bit sRGB RGBA（`DecodedImage`），并统一应用 EXIF 方向。
2. 进入编辑管线前转换为 **f32 线性 sRGB RGBA**（straight alpha，Rec.709 亮度权重）。
3. 当前工作空间固定为 `linear-srgb`，文档中显式记录；预览与导出都从同一线性管线输出。
4. 输出阶段统一转换为 sRGB 8-bit，再编码 JPEG / PNG / TIFF。
5. 首期不承诺 ICC 输入输出、广色域工作空间或 HDR；这些能力需要独立验证与 ADR。

## 后果

- 优点：曝光、白平衡、混合、模糊的数学行为一致且可测；CPU 与未来 WGPU 后端共享同一约定。
- 代价：解码和编码存在一次确定性的色彩转换；8-bit 输入的精度上限仍存在。
- 已知限制：未实现 ICC 解析、软打样与广色域输出；导出色彩为 sRGB。

## 验证

- 线性 ↔ sRGB 往返误差测试。
- 零参数色彩节点逐像素不变。
- 合成与模糊在 100% / 200% 下无可见色带或 gamma 错误。
