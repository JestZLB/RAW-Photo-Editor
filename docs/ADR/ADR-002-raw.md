# ADR-002：RAW 解码方案与首发兼容策略

- 状态：部分接入（rawler 基础解码，逐机型样片仍待验证）
- 日期：2026-10-21
- 关联：架构文档 07，风险清单

## 背景

RAW 是首期产品范围，但不同厂商的容器、压缩、色彩矩阵与白平衡差异很大。架构文档明确要求：不得因为某个 crate “能打开文件”就宣称完成 RAW 开发，且依赖必须在 Windows x64 干净环境构建并验证许可证与维护状态。

## 决策

1. 在独立 `raw-develop` 子系统中接入 **rawler 0.7.2**，完成“基础可用”的 RAW 解码路径：格式探测、解码器 trait、统一错误码与能力声明。首批明确覆盖松下 RW2/RWL、尼康 NEF/NRW、索尼 ARW，其他品牌按 rawler 相机数据库工作。
2. 导入路径优先使用原始 RAW 文件；解码结果只进入内存与项目缓存，原始 RAW 文件保持只读。AI Provider 不上传 RAW，改用生成的 sRGB 预览图。
3. 能力声明必须区分“已接入”和“已验证”：
   - 当前 UI 显示 RAW 已启用；
   - 已用松下 DC-FZ80（RW2）、尼康 1 J1（NEF）、索尼 DSC-RX100（ARW）真实样片验证导入、预览和导出；
   - 其他机型仍取决于 rawler 相机数据库，解码失败返回 `RAW_DECODE_FAILED`，不会回退成错误位图。
4. 正式发布前仍需完成：
   - 明确首发相机型号清单与授权样片；
   - 继续验证更多机型的方向、白平衡、色彩矩阵、压缩 RAW 与性能；
   - 审查 LGPL-2.1 许可证与静态链接合规方案；
   - 记录到兼容性矩阵并补充黄金样片。
5. 域层不依赖 rawler；替换解码器只需改适配器。
6. 方向处理：rawler 的 `raw_to_srgb` 输出保持传感器方向，不读取 EXIF 旋转。解码后读取 RAW 元数据中的 Orientation（0x0112）并应用对应的旋转/镜像，使画布尺寸、预览、裁剪与检测坐标都基于用户看到的正确方向。松下 RW2（EXIF 8）实测由 6000×4000 转为 4000×6000。
7. 旧项目修复：打开升级前导入的 RAW 项目时，如果元数据方向为 5..=8、存储画布仍是横置尺寸，并且没有坐标类编辑（全幅裁剪、无蒙版、无局部修复、无 AI 结果图层），解码原 RAW 后自动旋转预览、缩略图、画布与裁剪范围，并更新源尺寸。带蒙版、局部修复、AI 结果或已裁剪的项目不做自动迁移，避免坐标错位；这类项目建议重新导入原文件。

## 后果

- 优点：RAW 用户现在可以导入受 rawler 支持的机型；错误信息真实，不会静默产生破损图像。
- 风险：相机覆盖依赖 rawler 数据库，尚未逐机型验证；rawler 使用 LGPL-2.1，分发前必须完成许可证合规审查（见 `THIRD_PARTY_NOTICES.md`）。
- UI 必须同时显示“RAW 已启用”和“逐机型验证未完成”的边界。

## 验证

- 扩展名探测与能力声明有单元测试。
- 缺失文件返回稳定的 `RAW_DECODE_FAILED`。
- 已通过上述三款真实样片的导入/预览/导出；更多机型、方向与色彩回归仍待补。
- 真机验证：松下 DC-S5M2 的 P1023781.RW2 元数据为 Orientation 8，解码后得到 4000×6000（此前为 6000×4000 横置）；导入后的预览与文档方向一致。
- 旧项目自动修复验证：修复前该项目画布 6000×4000、预览 1600×1067；打开后自动重建为 4000×6000 画布与 1600×2400 预览，缩略图、项目摘要和初始画布比例同步更新，原始 RAW 未被修改。
