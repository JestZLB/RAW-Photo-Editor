# ADR-006：任务优先级、取消语义与资源预算

- 状态：已接受
- 日期：2026-10-20
- 关联：架构文档 09

## 背景

交互预览、人像分析、AI 请求与全分辨率导出会争用 CPU、内存与网络。滑块每帧触发渲染会淹没任务队列，过期结果还可能覆盖新状态。

## 决策

1. 任务分四级：`Interactive`（当前预览）、`Foreground`（用户触发的分析与 AI）、`Background`（缩略图/预取）、`Export`（全分辨率）。
2. 预览请求由前端合并/防抖；后端缓存以 revision 判断新旧，返回结果带 revision，前端丢弃过期响应。
3. AI 与导出任务携带 jobId 与取消令牌；预览以外的高成本任务可取消。
4. 取消只保证本应用停止等待与写入；不保证第三方服务立即终止远端计算，UI 必须说明。
5. 会话最多 3 个打开项目；预览缓存有上限；关闭项目可释放解码源图与可重建缓存。
6. 图像解码/渲染不在持有会话锁时执行，避免阻塞参数更新。
7. 任何长任务返回结构化进度与错误码；不通过高频 IPC 传输像素。

## 后果

- 优点：拖动滑块时最新状态优先，导出不饿死交互；内存占用可控。
- 代价：部分后台任务可能被延迟或丢弃；取消后远端可能继续计费。

## 验证

- 快速拖动滑块只显示最新预览。
- 取消任务后状态为 `cancelled`，无结果图层产生。
- 导出任务通过 `jobId` 推送阶段性进度；取消在阶段边界生效，未写入的目标文件不会残留，已存在的文件不会被删除。
- 3 个以上项目切换不崩溃，缓存可重建。
