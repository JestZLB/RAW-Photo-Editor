01. 执行摘要

这是一份用于技术设计与实施的基线文档，不是声称所有第三方依赖均已验证的最终选型。任何库、模型和 GPU 路径在进入主干前都必须通过 Spike / PoC。

产品目标快速人像、专业调色、RAW、自动修图、云端 AI 编辑
核心原则原图不覆盖、编辑可回放、AI 结果可审查、后端可替换
首发平台Windows 10/11 x64 优先；其他平台不作为首期验收门槛
交互优先级预览响应优先于后台分析和导出
AI 策略云端图像编辑优先；本地视觉模型可选；不绑定单一厂商
RAW 策略首期纳入范围，但需按相机样片建立兼容矩阵
架构主张：前端只负责交互与呈现；Rust 负责领域逻辑、资源与任务调度；图像处理后端可由 CPU、WGPU 或专用推理进程执行。不要把所有计算都强制塞进 GPU，也不要让云端模型成为本地确定性修图管线的唯一入口。

02. 架构决策与边界

领域基线决策说明 / 待验证项
桌面容器Tauri 2使用最小化 capability 权限；文件访问通过显式命令与授权范围控制。
前端React + TypeScript + Vite状态分为 UI 状态、文档状态、任务状态；不要将完整像素缓冲存入 React store。
Rust 工作区按领域 crate / module 拆分建议 core、document、render、raw、portrait、ai、persistence、app commands。初期可以 workspace 内模块化，避免过早拆成大量独立 crate。
图像计算CPU 参考路径 + 可选 WGPU 加速先实现正确性与可测基线，再将高收益算子迁移到 GPU；GPU 不可用时必须有可控降级策略。
RAW独立 RAW 开发子系统候选解码器须验证相机覆盖、色彩行为、许可证、维护状态和 Windows 构建；不得假设一个 Rust crate 覆盖所有 RAW。
AI统一 Provider 契约，云端优先供应商 API、兼容 OpenAI 风格的端点、图像编辑服务和 ComfyUI 都可能有不同能力；以 capability 描述实际功能。
持久化SQLite + 项目文档 + 资源缓存数据库存元数据和索引；大图、遮罩、AI 结果等二进制资源单独存储并以稳定 ID 引用。
色彩明确输入配置、工作空间与输出变换需要选定并测试具体色彩管理实现；不得只靠“支持 sRGB / P3”标签就宣称完整 ICC 工作流。
不在首期承诺：所有 RAW 相机型号均完美支持、跨设备像素级一致、所有 AI 模型都可取消、所有 GPU 输出逐像素相同、任意第三方模型工作流开箱即用。上述目标需要分别定义范围与验收方式。

04. 图像处理管线与执行图

将“固定顺序的整条流水线”调整为“固定的输入 / 工作 / 输出边界 + 可组合编辑节点”。节点之间需要显式声明依赖、颜色格式、分辨率、蒙版与执行后端。

① 导入与解码文件探测、EXIF 方向、RAW 开发、输入 ICC、缩略图
② 规范化统一像素格式、工作色彩空间、几何与尺寸元数据
③ 编辑图执行图层、调整节点、人像节点、蒙版、混合模式
④ 输出变换目标 ICC、位深、量化、锐化、格式编码与元数据策略

节点契约

字段用途
nodeId / type / schemaVersion稳定身份、算子类型、参数结构版本。
inputs / dependencies上游节点与资源依赖，保证合法拓扑顺序。
params经领域类型校验的参数；不允许未校验的任意 JSON 直接进入渲染器。
maskRef / opacity / blendMode局部影响范围与合成规则。
inputSpec / outputSpec像素格式、尺寸、色彩空间、动态范围等执行约束。
cacheKey / version根据上游内容、参数、算法版本与色彩设置计算缓存身份。
预览与导出分离：预览使用缩放代理图与可复用中间结果；导出使用原始分辨率和高质量参数。预览缩放不是最终图像数据。节点缓存必须区分预览尺寸、完整尺寸、色彩配置和算法版本。

WGPU 实施原则

  • 先建立 CPU 参考实现与图像基准测试，再迁移高收益算子；不要一开始就实现完整 GPU 图像框架。
  • 采用纹理池 / 缓冲池和预算驱动淘汰；GPU 资源丢失时可重建，不把 GPU 资源作为唯一持久状态。
  • 合并短小的颜色算子可减少 pass 开销，但要用实测验证；保留调试模式以便定位数值差异。
  • 对于高斯模糊、双边滤波等算法，分别测量分辨率、半径、精度、GPU 型号和驱动下的延迟。
  • CPU 与 GPU 采用容差、误差分布和视觉回归测试，不把跨后端逐像素相等作为普遍要求。

05. 项目文档、图层、蒙版与非破坏式编辑

图层类型

  • 原始图像 / RAW 开发图层
  • 调色调整图层
  • 人像处理图层
  • AI 编辑结果图层
  • 局部修复 / 克隆图层
  • 可选文字、水印或图形图层（可后续加入）

蒙版类型

  • 手动笔刷、橡皮擦、线性 / 径向渐变
  • 人脸、皮肤、头发、眼睛、嘴唇、背景等语义蒙版
  • 蒙版反转、羽化、密度、边缘细化
  • AI 蒙版作为可编辑资源保存，而不是仅保存模型请求

历史与恢复策略

  • 每个用户动作生成语义命令；滑块连续拖动合并为一条历史记录，避免每帧产生撤销项。
  • 大体积图像资源不重复塞进每条历史；历史记录引用资产 ID，并在需要时生成检查点。
  • 自动保存采用防抖写入 + 关键节点落盘；数据库事务和资源写入要设计一致性策略。
  • 启动时检测上次异常退出状态，提供恢复 / 放弃恢复；资源写入采用临时文件 + 原子替换等可靠策略。
  • 项目打开时校验 schemaVersion、资源缺失、算子版本与外部模型依赖，并提供迁移或降级提示。

06. 人像精修引擎

人像精修不是单个滤镜。需要把检测、关键点、分割、局部处理和合成拆成可测试模块；具体模型与算法需经过质量、许可和性能评估后选定。

建议的第一条可交付链路

1. 检测人脸框、关键点与置信度；允许人工选择目标人脸
2. 分割生成皮肤 / 五官 / 头发蒙版，并允许笔刷修正
3. 处理瑕疵弱化、肤色均匀、纹理保护与局部调色
4. 合成蒙版混合、实时预览、撤销重做与导出回归

产品交互原则：简单、直观、懒人化（必须遵守）

面向普通用户：用户不需要懂“蒙版、分割、羽化、色彩空间、关键点”等专业术语，也不应该为了修一张照片先学习教程。默认界面用日常语言、少量选项和安全的自动效果；专业参数放到“更多调整”里，不阻塞普通用户完成修图。
  • 先一键，再微调：提供“自然美颜”“清透提亮”“轻度精修”等一键方案。点击后立即预览，用户只需调整“效果轻一点 / 重一点”；不要求先选择模型、算法或复杂参数。
  • 默认效果保守：自动美颜默认使用自然、轻度效果，优先保留皮肤纹理和个人特征；不默认移除痣、胎记、雀斑、纹身，不默认大幅改变脸型或身体比例。
  • 把专业词换成人话：“语义分割”显示为“选择要修的部位”；“蒙版”显示为“修饰范围”；“羽化”显示为“边缘自然过渡”；“强度”显示为“效果程度”；“克隆”显示为“复制附近皮肤修补”。技术文档和内部接口可以保留准确术语，用户界面不要直接暴露。
  • 按目标组织，而不是按算法组织：首页分成“脸部美颜”“身体修饰”“皮肤颜色”“细节修复”几个容易理解的入口，不要让用户面对检测、分割、色彩管理等研发模块。
  • 自动找到，用户确认：优先自动识别人脸、皮肤和可修饰区域，并用清晰的区域提示让用户确认；识别不确定时显示“没找到合适区域，点一下想调整的位置”，不要静默地修错地方。
  • 重要功能一眼能开关：法令纹、黑眼圈、美白、痘印、痣、胎记、雀斑、纹身等使用独立开关；开关旁配一句简短说明。痣、胎记、雀斑、纹身默认关闭，开启后只处理用户确认的范围。
  • 用易懂的程度选项：默认展示“轻一点 / 适中 / 明显”或“自然 / 明显”预设；需要精细控制的用户再展开滑杆。避免一次展示大量数字、半径、硬度、色相、算法选项。
  • 随时知道改了什么：提供醒目的“按住看原图”“前后对比”“撤销”“恢复原图”；当前启用的效果清楚列出。关闭某项必须真正取消该项处理，不能只是把开关外观变灰。
  • 避免操作焦虑：编辑自动保存；所有效果可撤销；切换工具不丢失已完成修改；删除 / 覆盖原图前必须确认。遇到模型失败时给出普通用户能理解的提示和重试选项，不显示堆栈或内部错误代码。
  • 新手默认模式 + 可选高级模式：默认只显示常用功能和安全预设；“更多调整”里才提供笔刷、修饰范围、边缘过渡、细节保护等进阶设置。高级设置不应改变原图安全规则，也不能隐藏恢复功能。

建议的普通用户操作流程

1. 打开照片自动识别照片中的人脸和皮肤区域，不要求用户先设置参数。
2. 点一个效果例如“自然美颜”“皮肤提亮”或“修复痘印”，立刻看到预览。
3. 调整程度点“轻一点 / 明显一点”，或关闭不需要的单项效果。
4. 对比并保存按住查看原图，满意后点“导出照片”；原图始终保留。

人像算法需求规格（首期必须落地）

本节是算法研发、前后端联调和验收的共同需求。算法模型可以替换，但输入输出、用户控制、失败行为和质量测试不能省略。面向普通用户的操作必须遵循前述“简单、直观、懒人化”原则；专业参数默认收起。所有算法输出必须进入可撤销的编辑图层或节点，不得直接覆盖原图。

优先级 / 能力功能需求输出与交互要求验收重点
P0 人脸检测支持单人、多人、正侧脸、不同尺寸脸部；返回每张脸的边界框、置信度、稳定 ID。画布可选中目标脸；支持重新检测、忽略某张脸；检测结果与原图坐标系绑定。按脸部尺寸、姿态、遮挡分层统计漏检 / 误检；低置信度不自动套用五官处理。
P0 人脸关键点至少覆盖眼角 / 眼睑、眉毛、鼻翼 / 鼻尖、唇线、下颌轮廓；可扩展密集关键点。每个点带置信度；随缩放、旋转、裁剪和 EXIF 方向保持坐标一致。对不同姿态与遮挡进行关键点误差回归；失败时可手动修正或禁用依赖该结果的工具。
P0 语义分割生成皮肤、头发、眉毛、眼睛、嘴唇、牙齿、背景等类别蒙版；首期至少保证皮肤 / 五官 / 头发。蒙版可查看、反相、羽化、扩张 / 收缩；提供加 / 减笔刷、边缘修正和重置。重点检查发际线、眼镜、胡须、耳朵、手遮脸、复杂背景；蒙版边缘不得出现明显光晕。
P0 自然磨皮提供强度、半径 / 细节保护控制；弱化临时瑕疵与肤色不均，同时保留毛孔、细纹和自然质感。皮肤蒙版约束处理；眼睛、眉毛、鼻孔、嘴唇、头发默认排除；支持局部擦除效果。100% / 200% 查看不出现塑料皮、蜡像感、边缘涂抹和明显频率分离接缝；强度为 0 时结果应与输入一致。
P0 法令纹 / 细纹弱化针对法令纹、嘴角纹、额头纹、眉间纹、鱼尾纹、眼下细纹等提供分区、可调强度的弱化；区分纹理型细纹与阴影 / 凹陷形成的结构性纹路，不能一律模糊抹平。支持自动定位后手动增 / 减选区；每个区域独立强度、羽化、保护范围和前后对比；可只弱化阴影与局部对比，保留面部体积、笑容和自然皮肤纹理；效果单独成节点并可撤销。不同年龄、肤色、表情、侧光和正侧脸样片均需评审；不得出现鼻翼边缘融化、嘴角变形、面中平板化、肤色块、重复纹理或明显模糊带；强度为 0 时与输入一致。
P0 黑眼圈 / 眼袋修饰提供黑眼圈色差弱化、眼下局部提亮及轻度阴影减弱；眼袋结构调整与单纯色差修正应分开控制，首期不做不可控的自动重塑。眼下区域独立蒙版和强度；保护下眼睑边界、睫毛、眼角与眼球；提供自然 / 保守默认值与局部恢复笔刷。不把眼下区域漂白成纯色，不抹掉下眼睑轮廓，不产生眼睛大小或形状变化；检查强侧光、熬夜型色差及不同肤色。
P1 局部美颜组合在法令纹、额头纹、眉间纹、鱼尾纹、嘴角纹、颈纹等区域提供独立开关和预设组合；支持轻度瑕疵淡化、肤色均匀和局部提亮组合。组合仅作为可编辑参数预设，不合并成不可逆滤镜；显示每项实际启用的子效果，支持单项调节、重置、复制参数和局部擦除。验证多效果叠加时不出现过度平滑、边缘断层、脸型漂移或肤色失真；所有预设均可回到原图并可单独关闭。
P0 肤色均匀 / 局部调色支持肤色明暗和色相轻微统一、局部提亮 / 压暗；与全局曝光、白平衡、曲线及色彩空间正确衔接。强度、范围和蒙版可调；不得把全图白平衡或肤色修正隐藏地写入原始 RAW 参数。避免肤色漂灰、偏橙、偏红、过饱和；对不同肤色和混合光源单独评审。
P0 自然美白 / 肤色提亮支持全脸、身体和自定义区域的自然提亮；将亮度调整与色相 / 饱和度修正分开，支持肤色均匀、局部暗沉修正和暖 / 冷倾向微调。目标是照片中的视觉提亮，不改变用户真实身份或承诺改变生理肤色。独立控制提亮强度、肤色均匀度、色温倾向和作用范围；默认仅作用于皮肤蒙版，保护眼白、牙齿、头发、衣物与背景；支持脸部和身体分别调节、局部擦除及原图对比。多种肤色、混合光源、阴影、逆光及高光样片验证；不得出现死白、灰脸、偏蓝 / 偏粉、皮肤与脖子断层、五官边缘光晕或高光剪切；强度为 0 时结果与输入一致。
P0 特征性皮肤标记独立美颜开关痣、胎记、雀斑、纹身分别提供独立启用 / 关闭选项；启用后支持淡化或修复，不得将四类特征绑定为一个总开关。默认关闭自动修饰，用户主动开启后才处理。每类效果均提供独立开关、强度滑杆、目标区域选择 / 蒙版、局部擦除与恢复、前后对比、撤销重做；支持自动检测后由用户确认，也支持手动画笔指定。可选择“轻度淡化”或“尽可能移除”模式；纹身修复需标注为高风险生成式 / 内容重建效果，并输出独立图层。分别测试不同肤色、大小 / 颜色 / 密度、遮挡、毛发、衣物边缘与复杂背景；关闭时必须与输入图像一致。不得误伤相邻皮肤纹理、毛发、衣物或背景；生成式移除必须提示可能出现不真实纹理，并可一键恢复原貌。
P0 身体皮肤瑕疵修复支持可见皮肤区域的痘痘、痘印、临时红点、轻微色斑、局部色差、蚊虫叮咬印等修复；提供手动修复 / 克隆笔刷，自动识别仅作为辅助建议。支持身体皮肤蒙版与手动加减选区；笔刷尺寸、羽化、硬度、透明度、取样源、局部强度均可调；面部、颈部、肩臂、腿部等区域可分别处理；效果进入独立节点并可撤销。测试不同肤色、毛发、纹身、痣、雀斑、衣物边缘和复杂背景；默认不得自动删除痣、胎记、纹身等身份 / 个体特征；避免重复纹理、模糊块、接缝和背景被误修。
P1 身体肤色均匀 / 局部提亮支持颈部、肩部、手臂、手背、腿部等区域的肤色均匀、晒痕弱化和局部明暗调整；身体不同区域可分别控制。优先使用身体皮肤分割与用户修正蒙版；提供分区强度、过渡羽化、颜色匹配和保护区域，防止效果污染衣服、饰品、头发及背景。检查脸 / 脖子 / 手臂 / 腿部之间的色差过渡；不得出现肤色拼接线、边缘发光、皮肤蜡化或整体色调不一致。
P1 身体纹理与小范围修整支持轻度弱化细小疤痕、妊娠纹、干燥纹理、膝肘暗沉和局部压痕；结构性纹理必须保留可调节程度，不默认完全抹除。各项效果独立开关和强度；身体轮廓、关节、肌肉阴影及自然褶皱默认受保护；高级生成式修复必须单独标记并提供结果图层。避免把膝盖 / 肘部磨成无结构色块、身体轮廓漂移、肌肉阴影消失或衣物边缘变形；强度为 0 时无变化。
P0 瑕疵修复提供修复画笔 / 克隆工具，支持笔刷尺寸、羽化、硬度、透明度、取样源和对齐模式。笔刷轨迹可撤销；修复区域可受蒙版限制；支持笔触预览及取样点显示。测试痘痘、斑点、背景纹理、重复纹理和高反差边缘；不可产生明显重复图案或接缝。
P1 眼睛 / 牙齿增强眼白与虹膜局部提亮、细节增强；牙齿轻度去黄和提亮，避免全局高光漂白。依赖对应语义蒙版；每个子效果独立开关、强度可调、可局部擦除。眼白不变纯白、虹膜纹理保留；牙齿保留明暗层次，不出现蓝白色或过曝。
P1 液化 / 局部形变位移场或网格变形，支持推 / 拉、膨胀 / 收缩、笔刷半径、强度和冻结 / 保护区域。显示笔刷范围和形变前后对比；控制点 / 笔触可撤销；可保护背景直线、头发边缘和身体轮廓。检查建筑线条、门框、衣纹、发丝与身体边缘；限制极端位移并支持关闭 / 重置；不得静默自动改变身体比例。
P1 背景 / 发丝精修改进头发与背景边界，提供背景虚化或背景调整的可选蒙版基础。蒙版边缘可视化；用户能恢复被错误抹除的发丝 / 配饰；背景效果单独成层。逆光、卷发、半透明发丝、白衣白墙、眼镜边缘等困难样片无明显抠图白边。
P2 妆容 / 体型 / 高级重建虚拟妆容、唇色、腮红、局部塑形或生成式修复，作为可选扩展，不作为首期阻塞项。必须明确标识生成式结果；提供前后对比、区域蒙版、撤销和强度控制。单独进行真实感、身份一致性、伪影和用户可控性评审；不得与基础磨皮默认捆绑启用。

皮肤美白与身体瑕疵修复专项要求

产品原则：美白是对当前照片的可控视觉提亮与肤色协调，不应把不同肤色统一处理成单一白色。身体修复应默认“用户选择后修、保留特征、非破坏编辑”，痣、胎记、雀斑、纹身分别独立控制且默认关闭，不自动抹除用户可能希望保留的特征。
  • 面部与身体分区：面部、耳朵、颈部、肩臂、手部、腿部等皮肤区域需能分别选择与调节；自动分割不可靠时提供手动蒙版加减笔刷，且支持保存为项目资源。
  • 提亮与颜色分离：亮度 / 曝光、色温、色相和饱和度需独立控制。算法优先修正照片光照造成的暗沉与局部色差，避免通过大幅降低饱和度把肤色做成灰白色；保留阴影和高光的立体层次。
  • 修复工具：提供修复画笔与克隆工具，包含笔刷大小、硬度、羽化、透明度、取样源、对齐模式和撤销；可限制在皮肤蒙版内，支持按住查看原图、局部恢复和节点强度调整。
  • 瑕疵类别：痘痘 / 痘印、红点、轻微色斑、晒痕、局部暗沉、轻微疤痕、妊娠纹与干燥纹理可作为独立效果类别。痣、胎记、雀斑、纹身分别提供独立开关且默认关闭；只有用户单独开启对应功能并确认目标区域后才允许修饰。
  • 身体边缘保护：重点保护手指缝、腋下边缘、肩线、腿部轮廓、发丝、饰品、泳衣 / 衣物边界、纹身和背景直线；蒙版需支持边缘羽化、局部修边与保护笔刷，避免抠图溢出。
  • 一致性控制：可选启用脸部与颈部、肩臂等区域的色彩协调，但必须提供强度与禁用选项；不能把所有身体区域自动拉到相同亮度，也不能把自然阴影全部消除。
  • 验收样片：覆盖不同肤色、室内暖光、日光、逆光、混合光、皮肤高光、身体毛发、纹身 / 痣、浅色衣物、复杂背景及高分辨率图像；在 100% 和 200% 检查伪影，并在缩放适配画面检查整体肤色自然度。

痣 / 胎记 / 雀斑 / 纹身：独立开关与修饰模式

交互规则：四类特征必须各自拥有开关，互不影响。默认全部关闭，保持原图特征；用户开启某一项后，只处理该类被识别且经用户确认的区域。关闭开关应立即撤销该效果，而不是只隐藏控件。
  • 痣：单独开关；支持逐个选择、批量选择、强度调节与局部排除。提供“保留 / 淡化 / 移除”选项；不得因自动磨皮或肤色均匀而顺带抹除。
  • 胎记：单独开关；支持用户涂选或修正自动区域。提供轻度弱化与修复两种模式；大面积或边界复杂的胎记必须显示蒙版预览，避免肤色出现色块或边缘断层。
  • 雀斑：单独开关；支持降低对比度、降低可见度、保留部分雀斑等自然修饰强度。不得将雀斑检测结果直接作为全脸模糊区域，必须保留皮肤纹理。
  • 纹身：单独开关；支持局部淡化与移除两种模式。纹身移除涉及较大范围的内容重建，应使用独立修复图层 / 节点，允许预览、重新生成、蒙版修边和一键恢复；不能承诺所有复杂背景都能无痕恢复。
  • 检测与确认：自动检测只生成候选框 / 蒙版，不直接提交最终像素修改。置信度低、特征相互重叠或与头发 / 衣物 / 饰品相邻时，要求用户确认或手动修正。
  • 非破坏式实现：每类效果保存 enabled、mode、strength、maskRef、modelVersion 等参数；禁用后渲染图必须回到该节点输入，项目保存并重开后开关状态和蒙版保持一致。
  • 验收标准：逐项验证四个开关互相独立；开关关闭时像素输出不受该效果影响；强度为 0 时等同关闭；撤销 / 重做、保存 / 重开、复制参数和全分辨率导出均保持状态一致。

法令纹等局部美颜的专项算法要求

产品原则：目标是“弱化而非删除”。法令纹与眼下纹路常由面部几何、表情、光照和肤色共同形成，不能把它们简单视作需要擦除的瑕疵。默认采用轻度、可撤销、局部可控的修饰，保留真实的面部结构和身份特征。
  • 区域定义：建立法令纹（鼻翼至嘴角）、嘴角纹、额头横纹、眉间纹、鱼尾纹、眼下细纹 / 黑眼圈、颈纹等区域标签。检测模型可给出建议区域，但必须允许用户调整范围；关键点或分割低置信度时不得自动强修。
  • 分型处理：优先区分细纹纹理、色素 / 色差、局部阴影和结构性凹陷。分别使用纹理保留型平滑、局部色调 / 对比调整、受约束的阴影减弱；生成式补绘仅作为后续可选能力，不能作为首期唯一实现。
  • 边缘保护：保护鼻翼、唇线、嘴角、眼睑、下颌轮廓及高对比边界；区域蒙版需要平滑羽化，并避免效果越过法令纹走向污染鼻子或嘴唇。
  • 参数与交互：至少提供总强度、区域强度、过渡 / 羽化、细节保留和局部恢复；按区域分别开关；提供分屏 / 按住查看原图、撤销重做、单节点禁用和重置。禁止默认自动将所有纹路清零。
  • 高分辨率与预览：检测和蒙版可在代理图上运行，但须映射回原图坐标并检查边缘；导出阶段需全分辨率复算或经验证的高质量映射，避免放大低分辨率修补区域造成糊边。
  • 验收用例：同一人物微笑 / 中性表情、正面 / 侧面、顺光 / 侧光、不同年龄与肤色；同时检查法令纹变浅后面中体积是否仍自然、嘴角是否完整、皮肤纹理是否保留。由产品团队定义“轻 / 中 / 强”参考图并进行盲评。

算法处理顺序与图像质量要求

  1. 统一坐标：先处理 EXIF 方向并建立唯一的原图坐标系；人脸框、关键点、笔刷轨迹、蒙版、裁剪和液化控制点均保存为原图坐标或明确标注的变换坐标，禁止直接保存屏幕像素坐标。
  2. 先分析、后修改：检测、关键点、分割属于分析节点；磨皮、修复、调色、液化属于编辑节点。分析结果缓存要带图像资产哈希、模型版本、参数版本和坐标变换版本。
  3. 高分辨率一致性：交互预览可以使用代理图，但完整分辨率导出必须重新以原始尺寸计算或使用经过验证的映射；不能简单放大低分辨率蒙版而不做边缘质量检查。
  4. 色彩与精度：算法要声明输入 / 输出色彩空间、像素格式、数值范围和 alpha 处理方式；尽量在定义明确的工作空间计算，避免对 gamma 编码 RGB 直接进行不适当的模糊 / 混合。
  5. 纹理保护：磨皮必须区分低频肤色变化和高频纹理，至少提供保守默认值；不能将频率分离作为“质量保证”的唯一依据，最终以真实样片与盲测评审为准。
  6. 可控合成：所有算法效果以参数化节点 + 蒙版 + 混合强度合成；参数修改支持撤销 / 重做、保存 / 重开、复制到其他照片时的兼容性检查。
  7. 降级与失败：模型加载失败、GPU 不可用、低置信度、多人脸歧义、内存不足时，提示具体原因并提供手动工具 / CPU 回退；不得输出静默损坏的图像。

算法验收基线（建议目标，必须用自有测试集校准）

  • 建立授权且可重复使用的人像测试集，覆盖不同肤色、年龄段、性别呈现、脸部尺寸、姿态、光线、眼镜、胡须、遮挡、发型、多人脸和复杂背景；单独记录困难样片，不只用“好看”的样片。
  • 人脸检测 / 分割分别报告漏检、误检、IoU / 边界质量等适用指标，并按场景分桶；模型总体均值不能掩盖某一类人像明显退化。
  • 磨皮和局部增强由至少两类检查组成：自动图像回归（差异图、边缘、色彩变化）与人工盲评（自然度、纹理保留、身份特征保持、伪影）。
  • 为每个算法保存固定输入、参数、模型版本和预期输出；升级模型 / GPU shader 后执行黄金样片回归，允许有阈值的数值差异，不允许未经评审的明显视觉退化。
  • 质量指标应由产品和算法团队在样片评审后确定。未经实测，不得把某个准确率、耗时或“无伪影”作为已达成承诺。
  • 涉及人脸图片上传云端前，必须在具体操作处告知上传范围、用途、Provider、保留政策和费用（如适用）；默认不把人脸分析结果用于训练或其他用途。
明确边界：首期重点是可控的局部精修，不承诺所有照片一键完美。人脸 / 蒙版模型应当提供辅助而非强制自动修改；对于检测失败或模型不确定的区域，优先让用户确认。

07. 色彩管理、RAW 与导出

RAW 首期范围

RAW 支持必须以明确的相机样片矩阵验收。不同相机 RAW 的压缩方式、元数据、色彩矩阵和白平衡信息可能不同，因此不能简单地把“能读取文件”视为“完成 RAW 开发”。

子系统职责首期要求
格式探测识别扩展名 / 容器，验证文件并提取元数据支持格式清单、失败提示与样片测试集
RAW 解码解码、去马赛克、白平衡、黑电平与基础色彩转换明确所选库 / 系统组件的相机覆盖与许可证
RAW 开发参数曝光补偿、白平衡、色调、降噪、锐化（依实现能力）区分原始开发参数与普通 RGB 调整节点
输入色彩读取嵌入 ICC；无配置文件时按策略解释并提示有已知参考色块的测试图片
工作空间定义内部像素格式、色彩空间、计算精度和动态范围避免无记录的重复转换与过早裁切
输出目标 ICC、位深、编码质量、元数据保留策略JPEG / PNG 必做；TIFF 与高位深支持依依赖验证定范围

色彩流程

文件导入
  ├─ JPEG / PNG / TIFF：解码 + EXIF 方向 + 输入 ICC 解释
  └─ RAW：RAW 解码器 + 去马赛克 + 相机相关色彩 / 白平衡处理
                 ↓
       内部规范化工作表示
       (pixel format + working color space + precision)
                 ↓
       非破坏式编辑图执行
       (曝光 / 曲线 / LUT / 人像 / 蒙版 / 合成)
                 ↓
       输出色彩转换 + gamut handling + quantization
                 ↓
       编码 + EXIF / ICC 写入策略 + 文件校验

色彩相关的明确决策项

  • 选择内部工作空间与精度，并记录所有转换边界；不要只列出 sRGB、Display P3、Oklab 名称就视为完成色彩管理。
  • 1D / 3D LUT、.cube 解析、插值方式、混合强度和缓存烘焙应分别测试；不同插值可能产生数值差异。
  • 自动白平衡与自动曝光是建议值，不应无条件覆盖 RAW 原始开发状态；应作为可撤销节点。
  • EXIF 方向应在坐标模型中统一处理，液化控制点、蒙版和裁剪框必须与图像变换保持一致。
  • 导出需要处理文件名冲突、临时文件、磁盘不足、取消、写入失败和输出后校验。

云端模型优先，但 UI 与业务层不应绑定任何一家厂商。AI 能力应声明化；只有 Provider 明确声明支持的输入、输出和操作，产品才显示相应功能。

关键约束：
- Provider 原始响应必须先通过适配器解析与 schema 校验。
- 不将未校验的模型 JSON 直接写入编辑图。
- 参数建议需要范围限制、版本号、单位和语义定义。
- 图像结果写入新资产 / 新图层，不覆盖源图。
- 任务完成时检查 documentRevision；若文档已变化，提示用户选择应用方式。
- 超时、取消、重试、限流、认证失败与内容拒绝需映射到稳定错误码。

云端请求与隐私

  • 提供每个 Provider 的连接测试、模型名、API base URL、请求超时、图像尺寸限制与可选自定义请求头。
  • API Key 存入 Windows Credential Manager 或经过验证的安全凭据封装；不存前端持久化、项目文件或日志。
  • 上传前显示目标服务、图片范围、蒙版 / 参考图、预计发送的数据，并提供明确确认；记录可清除的任务历史。
  • 支持模型不可用、额度耗尽、限流、网络断开、上传失败、返回格式异常和服务端拒绝等情况。
  • 对于自定义 base URL，需要防范 SSRF / 本地网络探测：限制协议、重定向、目标地址与端口；对本地服务采用显式用户授权和单独策略。
  • 不能承诺所有服务都支持取消；若服务端不支持取消，应用停止等待并忽略过期结果，但需说明远端任务可能仍继续执行。
云端 AI 的产品规则：远程图像编辑通常会上传图像。界面必须明确提示数据去向，并为本地纯参数调整提供不上传图片的路径。供应商保留期限、训练政策和地区处理规则应以用户实际选择的服务条款为准。

09. 任务调度、内存与缓存

优先级任务类别调度策略
P0 交互当前画布预览、笔刷反馈、拖动滑块可合并请求；丢弃过期预览；限制并发，优先响应最新状态。
P1 前台人脸检测、分割、用户触发的 AI 请求可见进度；支持取消；避免阻塞交互预览。
P2 后台缩略图、预分析、预取缓存空闲时执行；可暂停或取消；设置 CPU / GPU 预算。
P3 导出全分辨率渲染与编码显式任务进度；可取消；不与交互任务争抢全部资源。

关键机制

  • 每个请求携带 jobId、documentRevision 和取消令牌；取消不等于保证底层第三方计算立即终止。
  • 滑块交互采用防抖 / 节流和任务合并；只展示最新有效请求结果。
  • 缓存键必须包含源资产内容标识、节点参数、蒙版版本、工作空间、分辨率与算法版本。
  • GPU 纹理池和 CPU 内存缓存都要设置预算；在内存压力、设备丢失或文档关闭时释放可重建资源。
  • 避免一次性常驻原图、多个全尺寸中间图、蒙版和 AI 输出；高分辨率处理按瓦片或阶段释放资源，具体策略以实测决定。
  • 所有长任务返回结构化进度与错误；不要通过高频 IPC 发送像素数据。

IPC 原则

允许跨 IPC

资产 ID、受控路径引用、节点参数 DTO、任务 ID、进度、错误、尺寸、元数据与结果引用。

避免跨 IPC

反复传输完整原图字节、全尺寸中间缓冲、无边界的 Base64 字符串和大量逐帧像素数据。

显示大图可考虑受控的 Tauri asset protocol、自定义协议或受权限约束的本地资源服务；具体方案必须按 Tauri 版本、Windows WebView2 行为和 CSP 进行验证，不应直接开放任意文件系统访问。

11. 安全、隐私与发布

桌面安全

  • 默认拒绝未声明的 Tauri capability。
  • 命令参数严格校验；路径操作防止目录穿越。
  • 前端 CSP 最小化；不允许任意远程脚本注入。
  • 外部 URL 使用白名单 / 用户确认打开策略。

AI 安全

  • 凭据不进入 JS 日志、项目文件或错误栈。
  • 请求日志默认不记录原始图片与完整提示词中的敏感内容。
  • 自定义服务地址防止 SSRF、重定向绕过与凭据泄漏。
  • 云端上传前明确提示并允许取消。

资源安全

  • 限制图片尺寸、解码时间、压缩炸弹风险与临时文件大小。
  • 校验导入文件真实格式，不仅信任扩展名。
  • 导入外部工作流 / 模型配置时进行 schema 校验。
  • 清理临时资源；日志与崩溃报告可脱敏。

交付与更新

  • Windows 安装包签名与版本策略。
  • 更新包完整性验证、失败回滚与发布通道。
  • 第三方库和模型许可证清单（SBOM 可作为发布门槛）。
  • 崩溃收集需告知用户并获得适当授权。

13. 分阶段实施计划

RAW 属于首期要求，因此 RAW 解码验证要在早期进行，而不是等其他模块完成后才处理。建议采用阶段门槛：每一阶段先通过技术验证和验收，再扩大实现范围。

PHASE 01–2 周 · 风险验证

技术 Spike 与架构决策记录 最高优先级

  • 建立 Tauri 2 + React + TypeScript + Vite 工程和 Windows 构建流水线。
  • 验证 RAW 候选库：样片覆盖、构建、许可证、解码结果与性能。
  • 验证 1–2 个云端图像编辑服务的真实 API、图片输入、结果获取、限流与数据政策。
  • 验证 WGPU adapter 可用性、简单 shader、设备丢失与 CPU fallback。
  • 记录 ADR：图像像素表示、色彩工作空间、项目格式、Provider DTO、凭据策略。

阶段门槛：关键依赖有 PoC 结果、许可记录和替代方案；未验证项清楚列出。

PHASE 12–4 周 · 应用骨架

项目、画布、导入与导出

  • 完成命令边界、错误模型、任务 ID、事件与取消协议。
  • 支持普通位图导入、预览、缩放、平移、前后对比。
  • 实现项目创建、保存、重开、原图引用与基础撤销重做。
  • 定义项目 schema、资源 ID、迁移版本和自动恢复最小闭环。

阶段门槛：图片可打开、保存项目、重开、进行一次基础调整并导出；原图不被覆盖。

PHASE 23–5 周 · 图像核心

RAW 开发、色彩管线与基础调色

  • 完成列入首发矩阵的 RAW 解码与基础开发流程。
  • 实现曝光、白平衡、对比度、曲线、HSL、LUT 和输出色彩转换。
  • 建立 CPU 参考算子、黄金样片、ICC / EXIF 回归测试。
  • 加入代理图预览、节点缓存和完整分辨率导出。

阶段门槛：RAW 样片能按支持矩阵导入；基础调色可回放；导出色彩与元数据策略可测试。

PHASE 33–6 周 · 人像基础

人脸、蒙版、磨皮与局部调整

  • 先建立人像黄金测试集与算法评审表；锁定人脸检测、关键点和分割的输入输出契约。
  • 完成皮肤 / 五官 / 头发及身体皮肤蒙版、人工加减笔刷、自然磨皮、肤色均匀 / 自然提亮和局部混合。
  • 实现法令纹、额头纹、眉间纹、鱼尾纹、嘴角纹、眼下细纹 / 黑眼圈的分区弱化；加入自然美白 / 肤色提亮、肤色均匀、身体痘印 / 红点 / 轻微色斑 / 晒痕 / 疤痕等瑕疵修复。各效果独立强度、蒙版、细节 / 轮廓保护、局部恢复和前后对比。
  • 实现修复 / 克隆笔刷、液化控制、冻结保护区域、坐标映射与撤销重做。
  • 增加眼睛 / 牙齿增强、发丝边缘优化作为可选节点；妆容和生成式重建后续再评估。
  • 验证低置信度处理、模型缺失、GPU 失败、全分辨率导出和不同肤色 / 光照的视觉回归。
